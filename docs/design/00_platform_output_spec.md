# 平台输出规格 — 小红书 / 抖音 横屏与竖屏

> **什么时候加载**：定渲染参数（分辨率/码率/CRF/fps）、排字幕与 UI 安全区时。
> 本文档是**输出参数的唯一权威处**；其他文档只写指针，不抄数值。

## 1. 本项目要出的 4 个成片

| 成片 | 时长（音频实测） | 横屏 | 竖屏 |
|---|---|---|---|
| 短视频 | **49.66 s** | 1920×1080 | 1080×1920 |
| 中视频 | **155.48 s** | 1920×1080 | 1080×1920 |

合计 **4 个 mp4**。有 BGM 时按 video-shotcraft 惯例**额外**出无 BGM 版（见 §5）。

## 2. 分辨率与比例

| 方向 | 注册尺寸 | 比例 | 适配平台 |
|---|---|---|---|
| 横屏 | `1920 × 1080` | 16:9 | 抖音横屏、小红书横屏、B站、视频号 |
| 竖屏 | `1080 × 1920` | 9:16 | 抖音竖屏、小红书竖屏、视频号竖屏 |

**fps 统一 30**，与字幕时轴（毫秒级）换算方便：`frame = round(ms / 1000 * 30)`。

> 为什么 30 而不是 60：源音频 24 kHz、素材是静态图 + 矢量动效，30 fps 足够；
> 帧数减半直接省一半渲染时间（渲染是最贵的一步）。

### 2.1 横竖屏如何共用一套代码

**原则：注册两个 Composition（`ShortLandscape` / `ShortPortrait` …），共用同一套镜头组件，
尺寸与布局由 `useVideoConfig()` 的 `width/height` 派生。**

否决 `--scale` 方案：`--scale` 只做等比缩放，1920×1080 缩到 1080 宽会得到 1080×608，
**不是 9:16**，无法改版式。所以横竖屏必须是两个 Composition、两个版式分支。

外部输入用**每个 Composition 各自一份 props JSON**，由 Python 侧用同一份 spec 渲染两次生成。

## 3. 编码参数（Remotion 渲染 CLI）

| 参数 | 值 | 说明 |
|---|---|---|
| `--codec` | `h264` | 平台通吃，兼容性最好 |
| `--crf` | `18`（横屏）/ `20`（竖屏） | 18 近视觉无损；竖屏信息量小，20 已足够且省体积 |
| `--pixel-format` | `yuv420p` | 必须，否则部分播放器黑屏 |
| `--audio-codec` | `aac` | |
| `--audio-bitrate` | `192k` | |
| `--concurrency` | 4（起始值，实测后调） | 见 [research/01_remotion_usage.md](../research/01_remotion_usage.md) |
| `--log` | `verbose` 调试 / `info` 正式 | |

预估体积：竖屏 50 s ≈ 8–15 MB，竖屏 155 s ≈ 25–40 MB。
**抖音/小红书单文件上限远高于此，无需担心**；但展示页上传建议 ≤10 MB。

## 4. 安全区（字幕与 UI 避让）

竖屏被平台 UI 覆盖的区域（**保守取值，按 1080×1920 计**）：

| 边 | 避让 | 原因 |
|---|---|---|
| 上 | 120 px | 顶部状态栏 / 平台标题 |
| 下 | 420 px | 抖音底部账号名、文案、音乐条、进度条 |
| 右 | 180 px | 点赞/评论/分享/头像竖排按钮 |
| 左 | 60 px | 保守留白 |

→ **字幕安全框：`x ∈ [60, 900]`，`y ∈ [120, 1500]`（1080×1920 内）**

横屏（1920×1080）：

| 边 | 避让 |
|---|---|
| 上 | 60 px |
| 下 | 140 px（平台底栏） |
| 左右 | 各 80 px |

→ **字幕安全框：`x ∈ [80, 1840]`，`y ∈ [60, 940]`**

> 结论：竖屏字幕**必须明显高于底部**（底部 420 px 不能放字），
> 这条直接影响版式设计 —— 竖屏主画面偏上、字幕条在 y≈1400 附近。
> 横屏相对宽松。

## 5. BGM 与音频版本

- 音频**源是成品混音**（24 kHz mono 旁白），本项目**不做 TTS**。
- 若加 BGM：按 video-shotcraft 惯例**同一时间线出两版**
  —— `with-bgm` 与 `no-bgm`（保留 SFX），靠 props 开关切换。
- **BGM 是否可生成、算力开销多少**：见 [research/04_bgm_and_audio.md](../research/04_bgm_and_audio.md)。

## 6. 交付命名约定

```
out/
  short/
    short_landscape_1080p.mp4
    short_portrait_1080x1920.mp4
    short_landscape_1080p_nobgm.mp4   # 若启用 BGM
    short_portrait_1080x1920_nobgm.mp4
  mid/
    mid_landscape_1080p.mp4
    mid_portrait_1080x1920.mp4
    ...
```

`out/` 只放成片与日志；**脚本绝不进 `out/`**（对照 minimax 的反例）。
