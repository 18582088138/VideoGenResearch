# 交付优化方案（branch `opt_deliver`）

> 目标：把「能出片」提升到「**可用于二次修改的交付物**」——
> 字幕、分镜片段、以及横竖屏两套独立设计。

## 一、本次交付物

| # | 交付物 | 形态 | 关键要求 |
|---|---|---|---|
| 1 | 完整成片 | `out/<set>/<kind>/*.mp4` | 横竖屏各一份 |
| 2 | **字幕文件** | `*.asr.srt` | ASR 识别；与语音对齐；**每条 15–20 中文字**（英文可放宽） |
| 3 | **分镜片段** | `out/<set>/<kind>/shots/NN_<type>.mp4` | **不渲染字幕**，一个分镜一个文件 |
| 4 | 分镜规格 | `spec.json` + props | 二次修改的输入 |

> 第 2、3 项是本次的核心 —— 用户原话：「这是视频二次修改的关键」。

## 二、诊断结论（实测，非推测）

### 2.1 竖屏效果差的三个叠加原因

| # | 问题 | 实测依据 |
|---|---|---|
| 1 | **可用空间被吃掉一半** | 竖屏安全区 `L60 R180 T120 B600` → 内容可用 840×1200（高占画布 **62.5%**，右被吃 16.7%、下被吃 31.3%）；横屏 1760×760（高占 70.4%） |
| 2 | **素材在竖屏被缩到最小边** | `ImagePanel.tsx:74-75` 硬编码 `maxH = safeHeight*0.62`。16:9 图在竖屏是**宽度绑定**→790×444（**占画布面积 16.9%**）；横屏是高度绑定→970×546（25.5%）。同一张宽图，竖屏必然最小 |
| 3 | **横竖屏不是两套设计** | 13 个镜头里 12 个只是 `portrait ? A : B` 换数值，**无一改变元素顺序/层级**；唯一例外 `FlowDiagram.tsx:125` 改了 `flexDirection` |

### 2.2 一个我上一轮引入的严重缺陷

**`TUNING` 的 11 个旋钮与 `scaleFromDesign` 全部零引用 —— 是死代码。**

上一轮我宣称「调风格只改一处」，实际只写进了 `theme.ts` 的定义，没有任何组件读它；
所有竖屏数值都是各组件**内联硬编码**（`TitleReveal.tsx:91` 写死 74/34、
`ImagePanel.tsx:75` 写死 0.62 …）。

后果：**「调竖屏参数」这件事目前根本不生效** —— 参数改了、界面无变化、完全静默。
这与项目既有的「不许有假配置」原则直接冲突，必须最先修。

### 2.3 文案与字幕重叠（已知实例）

8 个镜头用 `heroCenterY + panelH/2 + 常数` **手算**文案位置。
实测 `BeforeAfter` 竖屏下方文案堆到 y=1111px，与字幕块上沿 986px **已重叠**。

### 2.4 字幕质量不达标（实测）

| 素材 | 条数 | 中文字数 平均 | **落在 15–20 字的比例** |
|---|---|---|---|
| Omni-IO Skills | 22 | **9.5** | **18%** |
| 清华机器人 | 20 | **12.3** | **20%** |

时间轴无重叠、与 ASR 对齐良好，但**切得太碎** —— `max_chars=20 / min_chars=12`
加上对停顿过度敏感，导致平均只有 9–12 字。必须重新调参切分。

### 2.5 动效卡「只用了一半」

调研结论：本项目是工作区里**唯一真正消费 video-shotcraft 的项目** ——
但消费方式是「**只读 frontmatter 建索引**，不读正文」。

而卡的价值恰恰在正文里：

- `## 动效核心` —— 伪代码公式（`p = seg(t0, i·gap, i·gap+0.32, E.outCubic)`，三通道绑同一个 `p`）
- `## 参数表` —— 三列「参数 / 典型值 / 调节手感」，值是 `Easing.out(cubic)`、`stagger ≈3.5f`、`translateZ 60–320px`
- `## 已知坑` —— 必须遵守
- `## 参考实现` —— 指向调校过的 demo TSX，**那才是参数真相**

现状：LLM 只能看到卡名与一句话，**参数一个都没进上下文**；
组件是按语义手写的（`NumberRoll.tsx:1-15` 注释「实现 `odometer-digit-roll` 的语义」），
**没有按卡里的参数表实现**。这就是「动效没充分利用」的根因。

## 三、关键设计决策

### 3.1 素材占比：必须在方案里说清的几何约束

用户要求「保持长宽比不变，素材作为主体占画面 70–80%」。
**按面积算，这在数学上做不到** —— 以 1080×1920 竖屏放 16:9 素材为例：

| 素材宽度占画布 | 实际尺寸 | 占画布**面积** |
|---|---|---|
| 80% | 864×486 | 20.3% |
| 100%（铺满宽） | 1080×608 | **31.6%（上限）** |
| 要达面积 70% | 需 1080×1344 | 素材比例必须是 0.8:1（竖图） |

**结论**：保持长宽比时，竖屏放横图的面积上限约 **32%**。
所以「70–80%」只能理解为**主要维度**占比，即：

- 竖屏 + 横素材 → **宽度占 78–85%**
- 竖屏 + 竖素材 → **高度占 70–80%**
- 横屏 → **高度占 75–82%**（或左右分栏时宽度占 55–60%）

**本方案按「主要维度 70–85% + 素材是唯一视觉焦点」实现**，
并保证素材尺寸随画布派生（可通过 `TUNING` 调），而不是硬编码。

### 3.2 横竖屏两套独立设计

不再用 `portrait ? A : B` 换数值，而是**两套布局策略**：

| | 横屏（1920×1080） | 竖屏（1080×1920） |
|---|---|---|
| 结构 | **左右分栏**：素材占左 55–60%，文案右侧 | **上中下三段**：素材占上 45–55%，文案中段，字幕下段 |
| 素材 | 高度驱动，占画布高 75–82% | 宽度驱动，占画布宽 78–85% |
| 排版重心 | 水平流动（左→右） | 垂直流动（上→下） |
| 安全区 | L80 R80 T60 B260（字幕带上移） | L48 R48 T100 B560（**右边界从 180 收到 48**，因素材已居中不再贴边） |
| 字号 | 基准 1.0 | **按画布宽度等比缩到 0.62 左右**，再按内容量微调 |

**实现方式**：新增 `theme/layout.ts` 的 `deriveLayout()` 返回**结构化的版式对象**
（`mediaBox` / `textBox` / `captionBox` 三个矩形），组件只消费矩形，不自己算坐标。
这样「独立设计」是**结构上的**，不是三元表达式。

### 3.3 字幕：**不重切**，改为「核验 + 溢出闸」

用户口径已放宽：**5–20 个字都行，不用太严格；英文可适当增加**。

按此标准重新核验（用 `subtitle.weight()` 度量 —— 中文按字、英文按词 ×4，
这才是「英文可适当增加」的正确度量，纯数中文字会把 `Asset Registry` 这类条目误判为过短）：

| 素材 | 条数 | 权重 min/avg/max | **落在 5–20** | 越界条目 |
|---|---|---|---|---|
| Omni-IO Skills | 22 | 7 / 12.5 / 21 | **21/22 = 95%** | 1 条（权重 21） |
| 清华机器人 | 20 | 5 / 13.9 / 22 | **17/20 = 85%** | 3 条（权重 21–22） |

**结论：现有字幕质量已达标，不需要重切**（原计划的 `min_chars 12→16` 是依据过严标准，
已撤销）。越界的 4 条只超 1–2 个单位，且 `Caption.tsx` 对长条有自动缩字
（`captionShrinkAbove`），实际不会溢出。

改为做两件事：

1. **溢出核验（自动化）**：新增 `scripts/check_subtitles.py`，
   按「字号 + 安全框宽」算出每条是否会在画面上溢出或折行，
   作为交付前的闸 —— 这是「确保每一段字幕都满足显示的要求」的落地方式。
2. **对齐核验**：确认时间轴无重叠、与音频总长一致（当前实测 0 处重叠）。

### 3.4 动效卡真正用起来

1. **`shot_catalog` 增加正文抽取**：为每张卡抽出
   `动效核心`（伪代码）、`参数表`（结构化键值）、`已知坑`
2. **进入 LLM 上下文**：选卡后把该卡的这三节喂给规划器，
   让输出里带 `cardParams`（如 `stagger=0.055`、`ease=outCubic`、`digitMax=6`）
3. **组件读参数**：把卡参数作为 props 传入组件，替换现在的硬编码常量
4. **卡名校验**：所有卡名必须过 `library.json` 校验 ——
   这正是 `VideoGenResearch-minimax` 失败的原因（卡名是编造的，不在 157 张索引内）

#### 实证：`NumberRoll` 对照 `odometer-digit-roll` 的逐条差距

拿本项目最核心的一张卡（数字滚动是科技感视频的主力镜头）逐条核对，
证明「没充分利用」不是感觉而是事实：

| 卡的参数表条目 | 卡的要求 | 本项目实现 | 判定 |
|---|---|---|---|
| 字号/字体 | 190px fw800 + `tabular-nums` | ✅ `tabular-nums`（`DigitRoll.tsx`） | 符合 |
| 错峰 | `20+i×7f` 起停，从左到右 | ✅ `delay + i*stagger` | 符合 |
| 数位 | ≤6（每多一位多 7f） | ✅ 本项目数字都在 4 位内 | 符合 |
| 收尾 | 真静止 ≥45f | ✅ R1 已遵守 | 符合 |
| **过冲** | **+0.5 行再 6f 弹回** | ❌ **原本没有** | **已补**（`DigitRoll` 两段式落位） |
| 终值脉冲 | 加深 + 1.035 缩放 8f | ✅ `scale(1+pulse*0.035)` + `brightness` | 符合 |
| **残影** | **2 副本 0.25/0.12，速度门控** | ❌ 无 | **待补** |

**结论**：11 条参数里漏了 2 条，其中「过冲」被卡标注为命门 ——
原文「**无过冲读作滑到即停，机械感减半**」。这不是可选的装饰。

**这解释了为什么「动效不够精美」**：卡把参数写到了「+0.5 行、6f、1.035」这种精度，
而实现是照语义手写的，必然丢掉这些调校过的细节。

**方法论**：把「读卡参数」变成**可校验的代码路径**，而不是靠人读文档记得住 ——
下一批要把 157 张卡的「参数表」抽成结构化 JSON，组件按参数渲染，
并加一条测试断言「组件声明的参数与卡一致」。

### 3.5 素材不足时的图文扩展（含用户追加口径）

现有 `figure-panel` / `stat-compare` / `flow-diagram` 三个图文镜头已能承载表格/流程/对比。
本次增强：**内容必须来自原文**（表格行、流程步骤、架构层级），
由 LLM 从 `narration` + 素材语义标注中抽取，而不是泛泛而谈。

判据（写进 prompt）：**把文案里的专有名词与数字全都抹掉后，这段内容还成立吗？**
如果还成立，说明它是废话。

## 3.6 用户追加口径（本轮后期，优先级最高）

| 口径 | 落地方式 |
|---|---|
| **用素材的镜头不要再加文案** —— 「素材图片 + 动效已经足够了」 | 素材类 5 个镜头（`page-spotlight` / `scan-annotate` / `radar-reveal` / `slow-push` / `before-after`）**不再渲染任何镜头内文案**；素材从分栏区 `mediaZone` 改用**全幅区 `mediaZoneFull`**，因此素材显著变大（横屏 1020 → 1760 宽的区域，素材高度绑定到 650） |
| **素材数量不足时才用视频文案补充分镜** | prompt 与 user prompt 都加「素材优先」：先为素材安排镜头、**素材可以复用**（同图换动效或换 `targets` 即另一镜），用尽后才用图文三件套补足 |
| **竖屏暂停，精力放在横屏** | 竖屏代码保持一致（`layout.ts` 的改动两个方向都生效），但**不再专门调优竖屏观感** |

**判据统一为：有 `image` 就不写文案，没 `image` 才写文案。**

> 为什么这条口径是对的：素材类镜头原先在素材旁压一行 `text`，
> 结果是**素材被缩小给文案让位**，同时那行字也因为缺乏对比而读不响 ——
> 两边都削弱。去掉文案后素材可以占满内容区，动效成为唯一的信息载体。

## 四、实施批次

| 批次 | 内容 | 验收 |
|---|---|---|
| **B1** | 修 `TUNING` 死代码 + 版式重构为矩形结构 + 竖屏独立布局 | 改 `TUNING` 一个值，渲染出的画面真的变 |
| **B2** | 素材放大为主体（≥ 主要维度 75%）+ 消除文案/字幕重叠 | 抽帧确认占比与无重叠 |
| **B3** | 字幕重切（15–20 字）+ 对齐校验 | ≥70% 落在区间；无重叠 |
| **B4** | 分镜切片导出（不带字幕）+ 开关 | N 个分镜 = N 个 mp4，时长与 spec 一致 |
| **B5** | 动效卡参数化（读正文 → 参数进 props → 组件消费） | 组件不再有硬编码动效常量 |
| **B6** | 图文扩展镜头 + 内容来自原文 | 抽帧确认 |
| **B7** | 完整渲染 + 切片 + 字幕 + 抽帧品检 | 4 项交付物齐全 |

## 五、成本

## 六、待确认

1. **素材占比按「主要维度 70–85%」理解**（按面积数学上不可行，见 §3.1）—— 是否同意？
2. **分镜片段是否要保留音频**？当前倾向**静音**（片段用于看画面，音频碎片意义不大）。
3. 竖屏右安全区从 180 → 48：若平台按钮栏压住素材右缘可接受，则这样改；
   否则保持较大的右侧留白但素材居中（会牺牲宽度）。
